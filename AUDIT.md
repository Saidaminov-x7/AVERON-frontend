# Аудит storefront AVERON перед визуальной переработкой

Дата аудита: 2026-10-05  
Область: `AVERON_frontend`, с проверкой фактически зарегистрированных маршрутов в `AVERON_backend/apps/api/src/server.ts` и доступных экранов `AVERON_admin_panel/src/routes.tsx`.  
Визуальный референс: приложенные снимки qlo.kz (светлая, почти чёрно-белая витрина) и приложенные снимки текущего AVERON (тёмная витрина, крупные служебные карточки и ошибочное изображение админ-панели в товарной выдаче).

> Ниже сохранён исходный статический аудит и план. Фактическая доступность включаемых флагами провайдеров зависит от переменных production-окружения; где она не доказана кодом, это отмечено как открытый вопрос.

> **Решение владельца от 2026-10-05:** динамическая тема storefront из admin-panel не нужна. Реализация после аудита переведена на статические CSS-токены; `DesignTokensInjector` и неиспользуемые admin theme UI/provider удалены. Светлая тема является основной, тёмная сохраняет ту же геометрию и лишь мягко затемняет поверхности.

## 1. НЕСТЫКОВКИ / МЁРТВЫЙ КОД

### 1.1. Темизация storefront: backend есть, frontend не подключён

| Элемент | Статус | Нужен по продуктовой логике | Решение |
|---|---|---|---|
| `components/DesignTokensInjector.tsx` | **Не используется:** импортов нет, в layout не смонтирован. Применяет только локальные дефолты, включая синий `#2563eb`. | Да: backend уже хранит тему сайта и admin содержит UI для её редактирования. | **Доподключить**, но переписать источник: получать реальные токены из публичного endpoint, а не применять захардкоженные дефолты. Смонтировать один раз в locale layout. |
| `GET /site-settings/public/theme` | **Используется backend, не используется storefront.** Endpoint реально зарегистрирован через `siteSettingsPublicModule` с prefix `/site-settings`; возвращает `primaryColor`, `secondaryColor`, `backgroundColor`, `textColor`, `borderRadius`, `fontFamily`, кешируется в Redis. | Да. Это уже существующий публичный контракт для темы. | Добавить типизированный fetch в `lib/theme.ts` (либо расширить `lib/siteSettings.ts`) и передавать initial theme с сервера в injector, чтобы избежать вспышки неверной темы. |
| `tailwind.config.ts` | Используется; комментарий утверждает, что `DesignTokensInjector` динамически задаёт primary, хотя компонент не смонтирован. | Да. | Оставить связь Tailwind → CSS variables; исправить комментарий и fallback-токены. |
| `app/[locale]/globals.css` | Используется. Сейчас содержит статические `#34383c/#25282b`, Arial/Segoe UI, а также остаточные fallback `#2563eb` в scrollbar. | Да. | Сделать нейтральные qlo-подобные fallback-токены источником истины; динамическая тема должна только переопределять разрешённые переменные. |

Первоначальная рекомендация была довести pipeline “БД → public theme endpoint → CSS variables”, однако владелец выбрал **статичную тему**. Поэтому storefront не потребляет `/site-settings/public/theme`; палитра, радиусы и типографика фиксируются в `globals.css`, а Inter подключается через `next/font`.

Дополнительная межрепозиторная нестыковка: в admin-panel определены `AppearanceSettingsPage`, `AdminPanelThemePage`, `AdminThemeInjector` и `AdminThemeProvider`, но поиск по `src/routes.tsx` и остальному дереву не нашёл их потребления. То есть backend endpoints `/admin/theme` и `/admin/admin-theme` существуют, но текущая админка не даёт доступного маршрута к этим страницам и не применяет сохранённую тему. Это не следует молча исправлять в рамках ограниченной CSS/JSX-задачи storefront; вопрос вынесен в раздел открытых вопросов.

### 1.3. Дубли UI и подвешенные реализации

- `components/ScrollToTop.tsx` и `components/ui/ScrollToTop.tsx`: активен только UI-вариант через `AppChrome`; корневой вариант — **не используется**, удалить.
- `components/SmartSearch.tsx` и `components/ui/SmartSearch.tsx`: обе реализации существуют; текущий Header реализует поиск ещё раз внутри себя. Необходимо выбрать один контракт. Для данной итерации: не переносить бизнес-логику поиска, удалить только доказанно неиспользуемый корневой компонент после дополнительного точечного импорта-чека; визуально упростить активный Header.
- `components/LanguageSwitcher.tsx`, `components/ui/LanguageSwitcher.tsx`, `LanguageDropdown.tsx`, `LocaleSwitcher.tsx` и внутренний `Header.LanguagePicker`: пять реализаций одной области. Активный путь — внутренний picker Header. План: оставить один активный компонент, удалить неподключённые варианты.
- `components/ThemeToggle.tsx` активен в Header; `components/ui/ThemeToggle.tsx` — только re-export. Re-export не нужен, если внешних импортов нет; удалить после точечной проверки.
- `components/commerce/CatalogSelect.tsx` **используется** и корректно адаптирует общий `components/ui/Select.tsx`; это не дублирование, а commerce-обёртка. Оставить.
- Admin `src/components/ui/Select` и storefront `components/ui/Select` похожи по назначению, но находятся в независимых приложениях и имеют разные theme-контракты. Физически унифицировать их сейчас нельзя без shared package и расширения scope. Согласовать только семантические токены и UX; код не копировать между репозиториями.
- `DynamicSectionRenderer.tsx` используется через layout/content pipeline (нельзя считать мёртвым только по наличию `return null`). Оставить.
- `AIAssistant`, analytics trackers, `AuthInitializer`, viewport/settings и navigation trackers возвращают `null` намеренно как side-effect компоненты и реально смонтированы. Оставить.

### 1.4. Закомментированный/недостижимый код

- Массовых закомментированных альтернативных реализаций не обнаружено; комментарии преимущественно объясняют контракты.
- В `app/[locale]/layout-server.tsx` есть fallback `return null` при ошибке settings fetch — это достижимая деградация, не мёртвый код.
- `app/[locale]/pages/[slug]/page.tsx` содержит честное состояние «страница временно недоступна» при ошибке CMS — оставлять, не подменять вымышленными данными.
- Главная проблема не недостижимый JSX, а **фактически неверные данные**: приложенные снимки AVERON показывают изображение мобильной admin-panel как товар. Это не CSS-баг `ProductCard`; карточка честно отображает URL, пришедший из каталога. Исправление товара/медиа должно выполняться через admin/backend data flow и не входит в разрешённые визуальные изменения.

## 2. РАСХОЖДЕНИЯ СО СТИЛЕМ qlo.kz

### 2.1. Глобальные токены

qlo.kz на снимках использует белый фон, почти чёрный текст/CTA, тонкие серые разделители, почти отсутствующие скругления и тени. Текущий AVERON по снимкам — тёмный по умолчанию, с графитовыми панелями, крупными обводками и сервисными карточками.

Найденные расхождения:

- `--color-primary: #34383c` и `--color-secondary: #25282b` дают графитовый, а не почти чёрный акцент. Нужен fallback около `#1a1a1a`, а вторичный — нейтральный серый через переменные.
- `--color-bg: #faf9f7` тёплый; qlo ближе к чистому белому canvas. Поверхности должны отличаться минимально и только там, где нужна иерархия.
- `--radius-card: 0.5rem`, `--radius-control: 0.375rem`, глобальное принудительное округление `.rounded-*` визуально мягче qlo. Нужны меньшие значения через токены, без локальных `rounded-none`.
- Меню и toast используют выраженные `box-shadow`; карточки действий также используют `shadow-sm/hover:shadow-md`. В товарной сетке тени следует убрать, для dropdown оставить только минимальную функциональную глубину через переменную тени.
- В CSS остаются синие fallback `#2563eb` для scrollbar — прямое расхождение и утечка старой палитры.
- `--font-family` использует Arial/Segoe UI. Подключить `Inter` через `next/font/google` в root layout, выставить его CSS variable как безопасный дефолт и сохранить управляемое переопределение `--font-family`.
- В компонентах остаются hardcoded `rose-*`, `stone-*`, `slate-*`, `#e60023`, `black/white`. По заданному ограничению цветовые решения следует перевести в семантические CSS variables (`--color-sale`, `--color-on-primary`, `--color-image-surface`, `--color-overlay`, `--color-border-hover` и т. п.), а компоненты должны ссылаться только на них.

### 2.2. `components/commerce/ProductCard.tsx`

- Фото уже помещено в прямоугольник 3:4 без внешней рамки карточки — хорошая база.
- Одновременно выводятся скидка поверх фото и второй badge «Скидка» под фото; это дублирование и визуальный шум. Оставить один компактный текстовый маркер рядом с названием/ценой.
- Availability показан крупной полупрозрачной rounded-pill плашкой с blur/shadow. Для qlo-подобного стиля: компактная нейтральная строка/метка без тени; показывать только значимое исключение (предзаказ/нет в наличии), а не «в наличии» на каждой карточке.
- «Новинка» сейчас чёрная плашка; в qlo она очень компактна. Уменьшить и убрать из неё декоративную геометрию.
- Цена скидки hardcoded красная `#e60023`; перенести в `--color-sale`. Старая цена уже зачёркнута, но должна быть тоньше/компактнее и без заливки.
- Цветовые чипсы уже малы, но используют inline `backgroundColor` из фактического hex варианта. Это **данные товара, не theme color**, поэтому допустимо оставить inline; рамку/размер перевести на токены.
- Кнопки favorite/compare имеют тени, hover-тени и яркую rose-заливку. Оставить функционал, убрать декоративные тени, использовать монохромное состояние через semantic variables.
- Hover-смена второй фотографии — уместна и не меняет бизнес-логику; оставить.

### 2.3. `components/layout/Header.tsx`

- Header перегружен: поиск, язык, theme toggle, favorite, compare, cart, auth, mobile drawer и большая маркет-навигация конкурируют на одном уровне.
- В qlo основная строка визуально компактна: logo, категории, поиск, язык, заказы, вход, корзина. Предложение: на desktop вывести текстовые категории из реальных nav/settings, компактный поиск, язык, заказы/вход/корзину; favorite/compare оставить в account/utility группе или скрывать под более узким breakpoint, не удаляя функции.
- Theme toggle не соответствует почти полностью светлому qlo-референсу, но удалять его без продуктового решения нельзя. Оставить доступным в user/menu area, снизить визуальный вес.
- Сохранить текущую безопасную локализацию URL, auth/cart/favorites/compare логику и data-driven nav; менять только JSX-композицию и классы.
- Убрать тяжёлые borders/pills у каждого icon button, уменьшить число видимых иконок, увеличить расстояние между текстовыми категориями.

### 2.4. Главная `app/[locale]/(main)/page.tsx`

- Hero сейчас текстовый блок на `surface-soft`; по композиции похож на первый блок qlo, но AVERON использует слишком крупные заголовки и тёмную/графитовую подачу. Сделать светлый нейтральный блок, компактнее заголовок и шире спокойные отступы.
- Категории сейчас четыре большие текстовые панели `min-h-56` без товарных фото. У qlo категории представлены фотографиями. В коде нет подтверждённых category image URLs, поэтому **не выдумывать изображения**: на текущем этапе уменьшить высоту и визуальный вес плиток; отдельный вопрос — добавить реальные category media через backend/admin.
- Секции товаров уже используют повторяемый grid, но spacing и типографика крупнее qlo. Нужны более плотные карточки, более разреженные межсекционные отступы и 4 колонки на типичном desktop (с адаптивностью без изменения загрузки данных).
- Огромные пустые области на AVERON-скриншотах вызваны не только CSS, а наличием всего одного некорректного товара в каждой подборке. CSS не должен растягивать карточку; источник данных остаётся отдельной проблемой.
- Блок «Понятный заказ и доставка» и footer визуально тяжелее qlo; убрать крупные тёмные панели/обводки, сохранить контент и ссылки.
